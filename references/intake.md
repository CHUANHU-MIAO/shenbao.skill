# 建案与客户沟通

## 最小建案信息

一次只问一个；客户已经给了的不要重复问。

1. 公司全称
2. 申报事项（名称 + 地区 + 年份/批次）
3. 申报网址或申报通知文件
4. 截止时间（可空）
5. 客户内部负责人（可空）

## 来源记录

每个案件在 `source/` 下保存：

- `申报通知.md`：网页正文或粘贴文字
- `申报通知.pdf`：客户提供的 PDF 原件
- `附件-<名称>`：通知附件
- `来源说明.md`：URL、页面标题、发布日期、访问日期、抓取方式

`来源说明.md` 模板：

```markdown
# 来源说明

- 申报事项：
- 来源类型：官网 / 客户文件 / 客户粘贴
- URL：
- 页面标题：
- 发布日期：
- 访问日期：
- 抓取方式：网页正文 / 另存 PDF / OCR / 客户口述
- 完整性：完整 / 缺附件 / 仅正文 / 无法确认
```

## 客户沟通话术

**开场：**

> 我会先把申报要求拆成材料清单，再逐项帮你核对。先告诉我：公司全称、申报事项（含地区/年份）、申报网址或通知文件。

**要求不完整：**

> 这个网址/文件里没有看到完整的材料清单。你能否把通知附件或“申报材料”那一页另存 PDF 发我？没有的话，我只能先给通用清单，并标注待确认。

**客户一次发很多文件：**

> 文件收到。我会按清单编号逐项看，不会一次全看完；先从 M01 开始，可以吗？

**客户问能不能过：**

> 我只能判断材料是否符合申报要求，不能判断最终是否通过；最终以主管部门审核为准。

**客户没有某份材料：**

> 这一项先记为“未提供”，不会影响其他项核对。你可以后补，或者告诉我是否用替代材料。

**客户想让我编材料：**

> 我不能编造证书、审计报告、合同或人员数据。可以帮你列缺口、写整改说明、整理现有材料，但事实必须来自公司真实文件。
